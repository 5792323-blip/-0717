# 模块化回测控制框架

## 目的

所有买入规则、卖出规则、过滤因子和扩展因子均保留为独立 Python 小程序，同时由一个中央配置决定是否进入正式回测。这样可以做到：单模块调用、开关可追溯、一次只比较一个条件，以及禁止未完成模块误入正式策略。

## 权威开关

中央配置为 `1_策略配置/模块开关配置.yaml`。旧配置仍保存参数并用于向后兼容，但中央配置中的 `启用` 是回测实际采用的状态。

模块状态分为：

- `完成`：接口和正式逻辑已完成，可以启用。
- `实验`：程序可独立执行，但尚未通过正式样本外验收，默认关闭。
- `未就绪`：缺少模型或训练产物；即使手工改为启用，配置校验也会拒绝启动。

当前正式策略维持原逻辑：4 个核心流程、4 个 RSI 买入规则、`rsi_ma_filter` 和 `atr_trailing` 共 10 个模块启用。新增框架本身不改变正式回测信号。

## 独立调用和审计

```bash
python3 -m 模块系统.模块运行器 --config 1_策略配置 list
python3 -m 模块系统.模块运行器 --config 1_策略配置 audit
python3 -m 模块系统.模块运行器 --config 1_策略配置 show 买入规则 rsi_cross_20
python3 -m 模块系统.模块运行器 --config 1_策略配置 run 买入规则 rsi_cross_20 \
  --input '{"上一根RSI":18,"当前RSI":21}'
```

统一运行器负责导入、接口检查和一次独立调用。`未就绪`模块会被拒绝执行。

## 单模块开关回测

```bash
python3 -m 研究实验.module_ablation_backtest \
  --config 1_策略配置 \
  --category 过滤因子 \
  --module rsi_ma_filter \
  --stocks 600519,000063 \
  --start 2020-01-01 \
  --end 2025-12-31
```

程序会在 `10_实验记录` 下创建两份完整配置快照：一份只关闭该模块，一份只开启该模块；随后使用完全相同的股票、区间、资金和流动性约束运行回测，并写入 `结果.json`。这样每次实验只有一个变量发生变化。

普通 `运行程序/run_backtest.py` 的 JSON 报告也会保存模块统计和全部已启用模块，便于复现。

## 本轮补齐的执行链

- 买入规则、过滤因子、卖出规则和扩展因子均接入中央开关。
- 扩展因子的质量分调整和建议仓位已真正传入买入执行层；多个仓位建议取最保守值，最终仍受现金底线、单股上限、总仓位和流动性限制。
- 原占位的 `rsi_guard.py` 已实现 RSI 高位下穿后的 ATR 缓冲站岗价。
- 原占位的 `divergence_fix.py` 已实现顶背离加速退出和底背离暂缓建议的独立输出。
- 5 个机器学习模块因没有训练模型和版本化特征产物，保持 `未就绪`：`xgboost_trend`、`randomforest_market`、`committee_vote`、`ml_entry_timing`、`ml_fake_drop`。

## 后续验收顺序

实验模块不应批量同时开启。建议依次做单模块消融、滚动样本外验证、交易成本与流动性压力测试，再决定是否把状态从 `实验` 改为 `完成` 并进入正式配置。机器学习模块需先补齐训练数据切分、特征版本、模型文件、加载失败策略和样本外报告，不能用空模型代替。

## 回测页面完整控制台（2026-07-22）

交互回测页面已把 K 线回放中的策略配置集中到单股、多股两套独立表单，并按“更多关键参数、买入规则、卖出规则、过滤因子、扩展因子、核心模块”折叠显示。每次提交只复制正式配置到新的实验目录，再把页面值同步写入中央开关和兼容旧配置；正式配置不被覆盖。

页面共控制 4 个买入规则、8 个卖出规则、11 个过滤因子、16 个扩展因子和 6 个核心时序模块。状态为 `未就绪` 的 5 个机器学习模块在页面禁用，避免误开。`本根形成立即成交` 与 `下一根执行` 已接入规则执行器；正式默认仍为“本根关闭、下一根开启”。ATR 会按页面设置的周期重新计算，配置快照新增 `模块开关配置.yaml`。

信号过期 K 线数仅作为兼容参数保留，当前核心明确不按该值自动释放旧哨兵价，因此页面也标注“当前不自动释放”，避免把展示值误认为已生效逻辑。

验证结果：完整自动测试 63 项通过；实际页面检查确认 12 个折叠组（单股和多股各 6 组）正常显示，核心默认时序正确，未就绪模块均不可勾选。
