# Agent B 架构、数据流与代码简化审计报告

审计范围：当前工作树；只读检查生产代码和现有测试。未修改生产代码。本文把已有用户改动视为前置状态，不把测试通过等同于策略正确。

## 1. 实际核心调用链

### 单股路径

`运行程序/run_backtest.py:37,239-249` 导入并调用 `回测引擎.backtest_engine.跑回测`；`回测引擎/backtest_engine.py:119-121` 调用 `准备回测数据`，其内部加载股票、计算 RSI 和 ATR（`backtest_engine.py:44-90`）。`backtest_engine.py:131-151` 创建 `策略引擎.规则执行器.规则执行器` 并逐根调用 `每根K线处理`。

在执行器内，买入信号/哨兵状态/网格和卖出规则均在同一类中调度；成交价格使用 `成交模型/buy_fill_model.py`（`规则执行器.py:1453-1467`），买入股数、费用、现金/持仓更新和交易记录在 `规则执行器.py:1484-1812`；卖出价格、费用、现金/持仓更新和记录在 `规则执行器.py:2573-2679`。`交易记录器.py:229-245` 导出交易明细和持仓过程。`backtest_engine.py:161-246` 再计算单股摘要、权益、回撤和收益指标。

### 共享多股路径

`运行程序/run_backtest.py:320-331` 调用 `组合回测/统一多股执行器.py:249-655` 的 `运行共享账户回测`。该函数为每只股票调用同一个 `准备回测数据`（`统一多股执行器.py:298-317`），创建同一个 `交易账户` 的多个 `股票账户视图`，并把所有 K 线按时间放入统一时间轴（`统一多股执行器.py:319-343`）。每个时间点先更新开盘估值价、按组合优先级排序，再调用同一个 `规则执行器.每根K线处理`（`统一多股执行器.py:428-457`），收盘后更新估值并生成组合快照（`统一多股执行器.py:458-462`）。

共享账户结果随后由 `_整理股票结果` 读取执行器交易明细并重新计算股票归因（`统一多股执行器.py:155-205`），组合总损益来自 `account.权益()`，再与股票贡献合计对账（`统一多股执行器.py:625-664`）。

### 结果、报表、页面和回放

CLI 写入 `回测结果.json`、组合 `交易明细.csv`、共享账户 `审批记录.csv` 和 `运行清单.json`（`运行程序/run_backtest.py:405-443`），然后调用 `运行程序/可信度审计.py:444-448`。交互页面分别调用 `跑回测`/共享回测，并调用 `回测引擎.report_generator.生成报告`（`运行程序/interactive_backtest_app.py:3671-3682`、`4869-4872`）。多股回放从运行目录读取股票交易、持仓、归因和行情快照，再按需调用 `生成报告`（`interactive_backtest_app.py:4829-4872`）。

## 2. 架构问题

### ARCH-001：`run_id` 未贯穿交易账本和审批事实

- 问题类别：ARCH；严重级别：P1
- 涉及文件及行号：`运行程序/run_backtest.py:405-415`、`策略引擎/交易记录器.py:114-120,176-183`、`策略引擎/交易账户.py:174-176`
- 相关调用链：CLI 生成 `运行清单.run_id` → 执行器生成局部 `I/O/X` 编号 → 导出交易/审批 CSV；正常执行器记录行没有 `run_id`。
- 违反的不变量：INV-004、INV-008；共同约束“run_id 贯穿组合、股票、订单、成交和回放”。
- 触发条件：正常 CLI 或页面运行产生交易并跨运行目录合并/审计。
- 预期行为：每笔意图、订单、成交、审批和回放记录能由同一 `run_id` 直接反查。
- 实际行为：`run_id` 仅存在清单和可选事件日志；交易记录器只产生 `I00000001/O00000001/X00000001`，多股导出只在字段前加股票代码（`run_backtest.py:422-440`）。
- 最小复现：运行两次同一股票，比较两个目录的交易 CSV；除目录名外生命周期 ID 相同，CSV 本身无法证明属于哪次运行。
- 失败日志或数据证据：代码证据如上；`交易记录器.py` 的交易字典没有 `run_id` 字段。
- 影响范围：跨运行审计、页面回放与审批逐笔追踪可能误配；当前测试只验证股票前缀，不验证 run_id。
- 建议修复边界：在统一事件/账本边界注入并持久化 `run_id`，同步更新交易、审批和回放契约。
- 禁止修改范围：不要在页面层拼接或从目录名猜测 ID。
- 需要增加的测试：两次同参数运行的跨目录逐笔生命周期唯一性和双向关联测试。
- 风险：需要变更证据 schema；旧目录兼容需单独设计。
- 置信度：高；是否阻塞发布：是。

### ARCH-002：报表层保留独立的权益/哨兵兼容重算路径

- 问题类别：ARCH；严重级别：P1
- 涉及文件及行号：`回测引擎/report_generator.py:97-174,242-365,390-455`
- 相关调用链：执行器持仓过程/交易明细 → `生成报告`；当持仓过程缺失时，报告重新反推哨兵、交易定位和逐 K 线权益。
- 违反的不变量：INV-005、INV-008、INV-009。
- 触发条件：旧结果、缺失/空持仓过程或页面按兼容路径加载结果。
- 预期行为：报表和回放只消费真实交易事实；缺事实应显示不可用或失败。
- 实际行为：`_允许报告兜底重算 = not _有真实持仓过程`，随后调用 `智能反推`/`反推RSI价位` 并自行维护 `_当前现金/_当前持股`；这形成第二个事实计算器。
- 最小复现：构造只有交易明细和行情、没有持仓过程的结果，生成报告；报告仍会生成哨兵和权益，而非拒绝缺失事实。
- 失败日志或数据证据：代码证据如上；`生成报告` 同时包含执行器真实状态覆盖和兼容性重算两条逻辑。
- 影响范围：旧目录、手工构造结果和部分页面回放可能展示与真实执行器不同的收益/哨兵。
- 建议修复边界：先定义旧结果降级契约；默认阻断重算，仅允许明确标记的历史迁移工具执行。
- 禁止修改范围：不要直接删除兼容分支，必须先锁定历史结果行为测试。
- 需要增加的测试：有/无持仓过程、缺索引、组合实际成交三类结果的页面逐字段对账。
- 风险：历史报告兼容性；置信度：高；是否阻塞发布：是（对新基线）。

### ARCH-003：单股/共享多股结果经过两套收益事实整理

- 问题类别：ARCH；严重级别：P1
- 涉及文件及行号：`回测引擎/backtest_engine.py:161-246`、`组合回测/统一多股执行器.py:155-205,625-664`
- 相关调用链：执行器 `获取结果` → 单股 `backtest_engine` 计算收益/回撤；共享多股 `_整理股票结果` 再按交易账本复算归因并写回过程。
- 违反的不变量：INV-005、INV-006、INV-009。
- 触发条件：同一规则执行器在单股账户与共享账户运行，比较逐笔结果和每日过程。
- 预期行为：交易事实单一，组合差异只来自账户环境；派生指标应共享同一账本口径。
- 实际行为：单股摘要直接使用执行器 `最终权益/持仓过程.权益`；多股股票摘要改用 `_股票归因` 和 `_写入股票归因过程`，两套成本/市值派生过程并存。
- 最小复现：同一股票单股运行与单股票共享模式运行，比较交易明细一致但 `持仓过程` 的收益字段生成路径不同。
- 失败日志或数据证据：`tests/test_single_multi_parity.py` 仅覆盖选定列；未覆盖所有归因字段、拒单字段和每日现金/市值。
- 影响范围：逐日收益归因、页面字段和后续报表可能因模式改变而变化。
- 建议修复边界：先抽取唯一账本归因函数，再由单股/组合仅提供账户环境；行为差异需先由 A 裁决为 BUG 或 DESIGN。
- 禁止修改范围：不直接合并两套字段，避免掩盖口径差异。
- 需要增加的测试：单股/单股票共享的完整交易、持仓、费用、每日归因逐字段哈希。
- 风险：高；置信度：中高；是否阻塞发布：是。

## 3. 单股与多股重复实现

### SIM-001：账户结构性可用金额公式重复

- 问题类别：SIM；严重级别：P2（若行为不一致则升级 BUG/P1）
- 涉及文件及行号：`策略引擎/规则执行器.py:104-132`、`策略引擎/交易账户.py:100-133`
- 相关调用链：单股无账户视图时执行器本地计算；共享/单股账户均可能通过 `股票账户视图.计算结构性可用金额`。
- 违反的不变量：INV-001、INV-002、INV-009。
- 触发条件：现金底线、单只比例或总仓位比例为 0/边界值，或估值价缺失。
- 预期行为：同一公式、同一边界语义。
- 实际行为：相同业务公式维护两份；本地版本直接汇总 `当前持仓`，账户版本先更新估值价再汇总全账户。
- 证据：两段实现均计算 `现金可用金额/单只上限/总仓位剩余/min`，但输入来源不同。
- 最小复现：对同一账户参数分别调用执行器本地分支和 `股票账户视图.计算结构性可用金额`，记录返回金额与限制字典。
- 失败日志或数据证据：当前只有静态代码证据，尚无边界参数运行差异样本；因此保留为 SIM，不升级 BUG。
- 影响范围：未来修改一处公式可能使单股与共享账户的请求股数不同。
- 建议修复边界：先建立参数化 parity 测试；确认一致后只保留账户实现，单股通过同一账户视图。
- 禁止修改范围：在没有边界测试前不得删除本地实现。
- 需要增加的测试：0 比例、现金底线、已有多股票、缺估值价、最低一手等价性。
- 风险：中；置信度：高；是否阻塞发布：否（但阻塞安全简化）。

### SIM-002：费用模型重复且口径未统一

- 问题类别：SIM；严重级别：P2
- 涉及文件及行号：`策略引擎/规则执行器.py:1614-1620,2616-2621`、`组合回测/横截面组合.py:20-45,205-221`
- 相关调用链：规则执行器买卖成交费用；横截面组合独立维护 `交易费用`。
- 违反的不变量：INV-001、INV-009（仅当横截面组合被视为同一策略规则时）。
- 触发条件：小额成交、买卖方向切换、横截面组合与规则执行器使用同一配置时。
- 预期行为：同一策略产品的佣金最低值、印花税、过户费和滑点只有一个口径。
- 实际行为：佣金最低 5 元、过户费和印花税在多个位置重复计算；横截面组合还从 YAML 读取自己的成本结构。
- 最小复现：对同一成交金额分别调用规则执行器买入/卖出费用路径和横截面 `交易费用`，比较四项费用。
- 失败日志或数据证据：静态调用链已确认；尚无证明横截面组合属于同一策略产品的设计证据，因此不直接判定 BUG。
- 影响范围：费用、收益和组合对账可能因入口不同而变化。
- 建议修复边界：先确认横截面组合是否属于同一策略产品；若是，抽取唯一费用模型；若否，保留为独立实验并明确命名。
- 需要增加的测试：买/卖、小额最低佣金、滑点、印花税、横截面组合与规则执行器逐笔费用对账。
- 风险：中；置信度：高；是否阻塞发布：否。

## 4. 确认可安全删除的代码

本轮没有足够证据确认任何生产函数、类或模块“可安全删除”。已检查普通调用、import、页面回调、模板/JSON 路径和命令行入口；`run_backtest.py` 的 independent 入口、`report_generator.py` 的历史兼容分支、各模块 `__main__` 自检均仍存在可见入口或兼容价值。不得仅凭静态无调用结果删除。

## 5. 确认应合并的实现

尚无可直接合并而不先锁定行为的实现。优先候选是 `SIM-001` 账户可用金额公式；其次是费用模型，但必须先确定横截面组合是否纳入 INV-001 的“同一策略规则”。

## 6. 代码过长但不建议立即修改

- `策略引擎/规则执行器.py` 的买入/卖出主流程（约 1400-1815、2050-2191、2573-2679）：混合策略决策、审批、成交和账本，但行为密集；应先补逐笔行为基线。
- `回测引擎/report_generator.py:19-504`：同时承担事实读取、历史兼容、回放转换和 HTML 渲染；立即拆分会改变旧报告，当前只记录为 SIM/ARCH 风险。
- `运行程序/interactive_backtest_app.py:3986-4890`：多股页面生成、文件恢复、路由和兼容修复集中在一个模块；先做页面逐字段对账，再拆分。

## 7. 疑似冗余但证据不足

- `运行程序/run_backtest.py:239-249` 的 `执行单股任务` 与 shared 路径均调用 `跑回测`，但 independent 模式是明确的旧版独立账户对照，不能直接删除。
- `自适应基础设施/旧系统适配/旧执行器适配器.py` 仅在 `audit_run_id` 分支调用；动态审计和历史日志入口未完整排查，暂不判死代码。
- `回测引擎/横截面组合.py` 与统一多股执行器都做组合资金调度，但策略定义不同；行为差异证据不足，不能作为简单重复实现删除。

## 8. 建议简化顺序与锁定测试

1. 先锁定单股 vs 单股票共享的完整事实快照：交易、审批、拒单、费用、持仓、现金、市值、每日权益和归因。
2. 修复/统一 `run_id` 事件契约后，再做跨运行审计和页面回放反查。
3. 明确报表缺事实时的降级契约，禁止默认重算；为旧结果建立单独迁移测试。
4. 通过边界 parity 测试后合并 `SIM-001` 账户金额公式。
5. 最后评估费用模型和长函数拆分；每次拆分必须保持逐笔交易、每日权益、拒单和归因完全相同。
