# 策略0717 2.0 差距评估与实施规划

> 评估日期：2026-07-23  
> 评估口径：以当前实际代码、中央模块开关、真实成交链路和已有样本外实验为准；有文件但未改变成交/仓位/净值的，不算“完成”。

## 一、结论

当前策略不是单纯的 RSI 小程序，已经具备积木式模块系统、哨兵价执行、交易成本、决策回放、共享资金组合实验、复合因子研究和多种退出规则。但是这些能力分散在“正式单股/多股回测”“横截面组合研究”“扩展因子”三条支线中，还没有组成一条完整的 2.0 主链。

中央模块审计结果：

- 总模块 51 个；完成 13 个；实验 33 个；未就绪 5 个。
- 当前正式启用 10 个：4 个核心执行模块、4 个 RSI 买入规则、RSI_MA 过滤、ATR 跟踪退出。
- “实验”只表示程序存在并可调用，不代表通过样本外验证，更不代表已经进入正式策略。

按外部 2.0 方案拆成 40 个可独立验收的能力点：

| 状态 | 数量 | 占比 | 含义 |
|---|---:|---:|---|
| 已具备 | 10 | 25% | 已有实际执行或组合回测能力 |
| 部分具备 | 12 | 30% | 有相近程序，但口径、数据或主链整合不完整 |
| 尚未建立 | 18 | 45% | 当前没有可用实现 |

因此，不能直接把当前策略称为“0717 2.0”；更准确的定位是“1.x 模块化研究平台 + 2.0 的部分原型”。

## 三、外部方案中需要修正的地方

### 1. 不建议直接取消 RSI 买入

当前最成熟、经过多轮时序修复的是“RSI形成条件 → 反推价/哨兵价 → 价格触发成交”。直接取消会丢掉当前策略最有价值的执行层。

2.0 应保留三种可切换模式：

1. `RSI基线模式`：保持当前逻辑，用作长期对照组。
2. `Alpha纯排名模式`：前一日收盘评分，下一交易日开盘成交。
3. `Alpha + 哨兵择时模式`：Alpha决定买哪些股票，RSI/哨兵决定何时和什么价格买。

第三种是最值得优先验证的组合方式。

### 2. 市场状态应控制风险预算，不宜简单禁止交易

现有市场过滤在训练期改善、2024-2026验证期失效，说明硬开关容易过拟合。新市场分数应优先映射到 `目标总仓位`，并加入滞回区，避免分数在阈值附近造成频繁满仓/空仓切换。

所有日线市场状态只能使用上一交易日已完成数据。市场宽度必须使用当时可交易股票，不能用今天的成分股名单回填历史。

### 3. 基本面质量因子不能直接使用当前财报值

ROE、毛利率和盈利稳定性必须按财报实际披露日进入特征，并保留历史版本，否则会产生未来函数。没有可靠的历史时点数据前，质量因子应保持“未就绪”。

### 4. Top20每日全换仓会放大成本

现有20日反转组合已证明：信号有收益，但累计双边换手和回撤很高。2.0需要 `进入排名` 与 `保留排名` 两个阈值，例如 Top20进入、跌出Top60才退出，并限制每天最大替换数。

### 5. AI占30%不能先写死

70%人工 + 30%AI只是初始实验参数，不是结论。机器学习模块必须先证明样本外 IC、分组收益、校准度和扣费后增益，再逐级从0%增加权重。

## 四、建议的 2.0 主链

```text
历史时点股票池
  → 前一日市场评分（只决定风险预算）
  → 前一日个股因子快照
  → Alpha评分与横截面排名
  → TopN候选 + 保留区/换手缓冲
  → 可成交、流动性、风险过滤
  → RSI哨兵择时 或 次日开盘执行
  → 风险平价目标仓位 + 单股/行业/总仓限制
  → 共享现金组合成交
  → Alpha失效/时间/ATR/市场风险退出
  → 组合净值、归因和样本外报告
```

每一层都必须是独立模块、独立开关、独立参数，并在决策记录中输出“输入、结果、是否拦截、对仓位的影响”。

## 五、按当前策略实施的阶段规划

### Phase 0：冻结双基线

目标：后续升级不破坏当前策略，也不混淆两种回测口径。

- 基线A：当前正式 RSI + 哨兵 + ATR 策略。
- 基线B：现有20日反转共享资金组合。
- 固定股票池、日期、复权、成本、执行时点和随机性。
- 主页面增加“策略模式”，两套基线配置互不覆盖。

验收：相同配置重复运行结果一致；所有成交能追溯到前一时点可用信息。

### Phase 1：组合回测主链统一

这是第一优先级，不先重写Alpha。

- 把共享资金、现金竞争、整手成交和组合权益接入回测主页面。
- 多股模式不再用“单股结果平均”代替真实组合净值。
- 补齐 Sharpe、Sortino、Calmar、月度收益、换手率、回撤恢复时间、基准超额。
- 增加涨停、跌停、停牌、无成交量和不可成交处理。

验收：逐日满足 `总权益 = 现金 + 持仓市值`，不存在超卖、负现金、重复占用资金和当日未知数据。

### Phase 2：Market Score v1

- 独立建立趋势、ATR分位、宽度、流动性四个子模块。
- 每个子模块单独开关和调参，再由聚合器形成0-100分。
- 市场分数只控制目标总仓位，不直接否决单个信号。
- 先只使用沪深300，避免同时扩大数据问题。

验收：单因子消融、组合消融和2024-2026封存验证均有报告；若不改善回撤/收益比则保持关闭。

### Phase 3：Alpha Score v1（只用可靠价量数据）

- 先建立技术反转、趋势动量、资金流、风险四类；质量因子暂不加入总分。
- 每个原始因子统一做截面去极值、标准化、方向锁定和缺失值处理。
- 输出个股总分、分项贡献、当日排名和进入/保留原因。
- 同时回测 Alpha纯排名、RSI基线、Alpha+哨兵三种模式。

验收：权重只用训练期确定；验证期不重算方向和权重；报告包含IC、分层收益、换手和收益集中度。

### Phase 4：风险平价与组合约束

- 新增逆ATR/逆波动目标权重模块。
- 加入单股10%、持仓10-20只、总仓位和现金底线。
- 行业约束等拿到历史时点行业数据后再启用。
- 增加目标权重偏离阈值，偏离不足不交易。

验收：仓位和风险贡献可解释；高波动股票自动降权；成本后指标优于等权对照。

### Phase 5：Alpha失效与市场减仓退出

- 新增“跌出保留排名”退出。
- 统一时间、ATR、止盈、市场减仓的检查顺序与冲突规则。
- 市场风险下降优先做目标仓位再平衡，不直接按最低价假设全部成交。

验收：每笔卖出只有一个主原因，同时保留其他命中条件；退出模块可逐个消融。

### Phase 6：中证500与质量因子

- 建立可按日期查询的历史成分股接口。
- 获取按披露日可用的财务数据和历史行业数据。
- 股票池、财务数据缺失和新股上市天数均纳入过滤。

验收：无幸存者偏差、无财报发布日期未来函数；沪深300和中证500分别报告，不混为一个总体平均。

### Phase 7：LightGBM Alpha辅助

- 标签改为未来20日相对股票池基准的超额收益。
- 使用滚动训练/验证，不随机拆分时序样本。
- 初始AI权重为0，只做旁路评分；通过封存验证后再测试10%、20%、30%。
- 保留“纯人工Alpha”作为永久对照组。

验收：必须同时改善扣费后收益回撤比、IC稳定性和分层单调性，不能只看分类准确率。

## 六、第一批建议实际开发内容

下一轮建议只做以下四项：

1. 在主页面加入 `RSI基线 / Alpha纯排名 / Alpha+哨兵` 三模式框架。
2. 把现有共享资金组合引擎接入多股主回测，统一净值和成交口径。
3. 补全组合绩效指标与不可成交规则。
4. 建立 Market Score v1 的四个独立子模块和一个聚合模块，但默认全部关闭。

暂不做中证500、基本面质量和AI。这三项都依赖新的历史时点数据或更严格的训练体系，提前写开关只会增加“看起来完成、实际不可用”的占位模块。

## 七、最终判断

外部方案方向正确，但“取消RSI、一次性改为Alpha、再加AI”的跨度过大。最适合当前策略的升级方式是：

> Alpha负责选股，市场分数负责总风险，RSI哨兵负责择时与成交，风险平价负责买多少，共享资金组合负责真实净值。

这样既保留当前策略已经修复成熟的执行优势，也能逐步验证新的Alpha来源，而不是推倒重来后失去可靠对照组。
